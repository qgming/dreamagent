# DreamAgent v0.1.5

v0.1.5 重点完善会话自动执行、提示词库和模型输入能力。此次更新把提示词从页面内置数据升级为可校验、可打包的本地资源，同时让目标审计、会话标题、附件传递和创作区操作更贴近实际写作工作流。

## 提示词库

- 新增独立的提示词库页面，并加入左侧通用导航。页面采用“分类树 + 内容区”布局，分类支持展开和收起，当前分类中的提示词数量和条目状态可以直接扫描。
- 内置分类拆分为写作、人物、情节、场景和检查五组。移除默认的“自定义”分组，避免内置分类和用户分类混在一起。
- 用户可以创建、重命名和删除自定义分类。删除分类时，其中的自定义提示词会移动到“写作”分类，避免删除分类造成内容丢失。
- 用户可以新建、查看和编辑提示词。内置提示词允许直接编辑，用户提示词和内置提示词的编辑状态都会保存在本地。
- 内置提示词改为资源文件管理：`resources/prompts` 下每个默认分类对应一个 JSON 文件，文件包含分类信息和提示词内容。
- 新增主进程提示词资源服务、IPC 和 preload API，兼容开发目录、打包资源目录和 `electron-builder` 的 `extraResources` 路径。
- 新增资源格式校验，检查分类 ID、文件名、提示词 ID、必填字段和重复 ID；资源损坏时不会静默加载错误内容。
- 修复旧版本本地数据导致内置提示词全部落入同一分类的问题。现在内置提示词的所属分类以内置 JSON 为准，用户编辑的名称、说明和正文覆盖仍会保留。
- “恢复默认”调整为单条操作：只在当前内置提示词的编辑页面显示，仅恢复当前提示词的名称、说明、正文和分类，不影响其他提示词或用户分类。
- 输入框新增提示词库入口，选择流程与 `@` 引用组件保持一致：先选择分类，再选择具体提示词，选择后直接填入当前输入框。
- 统一提示词选择器与 `@` 引用选择器的面板尺寸、圆角、边框、阴影、行高、返回操作和条目样式。
- 提示词库入口和侧边栏提示词入口统一使用 Lucide `Leaf` 图标。
- 调整提示词分类列表的条目密度：保持顶部留白，减少说明文字下方的底部留白，让同一分类下的提示词更紧凑。

## 模型附件能力

- 根据当前选择模型的 `attachment` 和 `inputModalities` 自动判断是否允许添加附件。
- 仅支持文本输入的模型显示文本附件类型，包括 Markdown、TXT、JSON、CSV、XML、HTML、CSS、JavaScript、TypeScript、YAML、TOML、SQL、Python、Java、Go、Rust、Shell、日志和字幕等常见格式。
- 支持图片输入的模型增加图片附件能力，并允许 PNG、JPG、JPEG、GIF、WebP 等图片类型。
- 附件入口只开放当前传输链路真正支持的文本和图片类型；音频、视频、PDF 等无法由当前统一模型协议直接传递的类型不会显示为可上传类型。
- 模型不支持附件时禁用添加按钮并给出对应提示；切换模型后，已添加但不再支持的附件会自动移除。
- 文本附件会解析为消息文本，图片附件会转换为模型可用的 base64 图片数据，并保留附件名称和 MIME 类型。
- 修复运行时模型输入模态被硬编码为 `text` 的问题；现在使用模型实际的 `inputModalities`，视觉模型不会再收到“图片已省略”的占位文本。
- 修复图片附件只停留在输入组件状态、没有进入实际模型请求的问题；首次发送、运行中插话、排队消息和重新生成都能传递图片。
- 用户消息现在保存图片附件并使用缩略图展示，不再直接显示 `[附件:图片 ...]` 内部占位标记；历史会话中的图片也能恢复显示。
- 仅发送图片时自动提供默认图片分析提示词，避免因没有正文而无法提交消息。
- 附件预览、删除、上传失败状态和发送时的文本/图片组合逻辑得到统一处理。

## 会话标题与目标执行

- 新增独立的 AI 会话标题生成服务，根据第一次用户输入生成不超过 20 个字的中文标题。
- 标题请求使用当前选择的模型和低推理强度，并采用独立的非流式请求，不阻塞已经完成的创作回合。
- 标题生成失败、返回异常或内容为空时自动回退到本地标题，避免会话列表出现空标题。
- 标题生成结果通过新的 `session_title` 事件异步同步到创作区，页面无需等待标题请求才能结束当前回合。
- 会话目标审计改为独立的只读 Harness，可按需调用 `list`、`read` 和 `text_stats` 核验项目事实，不允许写入、编辑、删除或网络操作。
- 目标审计同时参考原始目标、会话最后一条可见消息和项目快照，不再只依赖最后一条消息的“已完成”描述。
- 目标审计统一使用严格 JSON 返回格式，并为 OpenAI Chat Completions 请求启用 JSON 模式，减少格式解析失败。
- 目标只有在全部可验证条件满足且有项目证据时才会标记为完成；失败、中止、等待用户或证据不足时会继续或暂停，不会误报完成。
- 目标审计状态、进度、下一步和证据继续通过创作区事件同步，并保留目标数据的本地会话存储语义。

## 故事人味化技能

- 更新 `story-humanizer` 技能到更完整的统计、基线比较、诊断、口语化编辑、保真复核和交稿验收流程。
- 补充对叙述口语化、听读节奏、复杂书面句、角色声线、重复模式和事实漂移的处理规则。
- 新增和完善检测评分、问题诊断、修改手册、交稿验收、禁词与句式、改写范例及人类文风基准资料。
- 增加内置人类文风样文，支持按题材和语气选择参考材料，不把统一的检测分数或固定句式当作所有题材的硬标准。
- 强化正文统计、参考样本、修改保真和验收之间的衔接，要求修改后核对数字、专名、对白和正文版本变化。

## 界面与基础维护

- MCP 侧边栏入口和 MCP 空状态图标统一替换为 Lucide `ToolCase`；其他非 MCP 场景的工具图标保持原有语义。
- 抽取通用单行名称输入组件，供提示词分类和其他名称编辑场景复用。
- 更新提示词、附件、会话目标和标题相关的共享类型，减少 renderer 与主进程之间的隐式数据转换。
- 增加提示词资源、模型附件能力、目标审计和会话标题的回归测试。

## 兼容性与验证

- 用户创建的提示词、分类以及已经编辑过的内置提示词继续保存在本地；恢复默认只替换当前内置提示词。
- 旧版本内置提示词的错误分类会在资源重新加载时自动纠正，用户编辑的标题、说明和正文不会被覆盖。
- 内置提示词资源会在开发环境和安装包环境使用不同路径自动解析，打包配置已将 `resources/prompts` 放入应用资源目录。
- 发布前通过 Node/Web TypeScript 类型检查，完整测试集共 12 个测试文件、66 个测试通过。
- 回归测试覆盖提示词资源校验、提示词分类、会话标题、目标审计、模型附件能力、图片消息转换和会话目标状态。
