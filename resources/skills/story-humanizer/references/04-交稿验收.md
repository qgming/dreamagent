# 04 交稿验收

> 验收同时看可测结构、人工质量和语义保真。没有任何一项能单独证明文本“像人”或“不是 AI”。

## 一、自动复核

- [ ] 修改后已重新运行 `text_stats`
- [ ] `structureScore` 和 findings 已记录；warning/error 已逐项解释或处理
- [ ] 句长、段落、逗号、句首和重复数据与作者基线或题材目标相容
- [ ] 对话策略与章节功能一致；没有为了比例插入无功能对白
- [ ] 重复句、重复短语和固定搭配已判断是有意还是无意
- [ ] `text_compare` 已检查数字、百分比、保护词和对白变化

`structureScore=100` 只表示当前规则没有扣分项，不是质量分、作者认证或第三方 AIGC 分数。内置 5 篇样文必须通过回归测试，但不作为所有作者的硬模板。

## 二、人工质量检查

每项 1-10 分，记录一句证据：

| 维度 | 检查问题 |
|---|---|
| 场景功能 | 本章是否推动事件、关系或认知变化？ |
| 声音 | 叙述者和主要角色是否有可辨认的立场与语言习惯？ |
| 节奏 | 长短、停顿和信息释放是否服务场景，而非像固定节拍？ |
| 具体性 | 细节是否来自现场，是否减少了空泛总结？ |
| 信任感 | 是否过度解释，或把读者已经知道的内容重复说了一遍？ |
| 保真 | 时间线、数字、专名、视角和对白意图是否保持？ |

总分只用于本次修改前后比较，不设置跨题材的硬阈值。任何一项低分都要回到具体句段，而不是整体重写。

## 三、交付内容

- 修改后的正文文件
- 结构复核报告：字数、段数、句长/段长分布、重复和对话策略
- 作者基线报告：参考来源、样本数、距离和需要解释的偏离项（如有）
- 保真报告：`text_compare` 的结果与人工确认结论
- 人工质量检查：得分、证据和仍需作者决定的项目
- 一句话说明本轮实际修改了哪类问题

## 四、外部检测反馈

如用户提供第三方检测结果，只记录检测器名称、版本或日期、文本长度、分段方式和结果。不同检测器之间不能合并成一个“真实 AI 率”，也不能用一次结果反向要求文本破坏语义或作者声音。
