# 03 修改手册

> 只修已定位的问题。网络小说用户要求整体口语化时，可以按段落连续润色，但仍要保留作者的视角、态度、口头习惯和题材词汇，优先做能说明收益的修改，不把正文压成提纲。

## 修改前

1. 保存正文原文和 `text_stats.sourceHash`。
2. 局部任务从诊断报告中挑选最多一到三个最高收益的问题；如果用户要求整章口语化，则按段落或场景分批处理，每批仍先处理最影响听读的句段。
3. 把时间、数字、人物、地点、专名、关键物件和对白意图列为保护项，传给 `text_compare`。
4. 读目标行和前后文，确认修改不会跨越视角、时间线或场景边界。

## 修改顺序

1. **保真层**：纠正或恢复事实、视角、因果和专名。
2. **听读与口语层**：把复杂书面句换成能顺着读的常用表达，给动作和情绪留自然落点。
3. **场景层**：删掉重复解释，让行动、关系或认知真正发生变化；该保留的自然冗余不要顺手删光。
4. **段落层**：只拆信息混杂的大段，或合并机械碎段；允许一行停顿段和较长的讲述段并存。
5. **句子层**：处理重复句式、空泛总结、不自然连接和多层套句。
6. **节奏层**：让长短变化服务于紧张、停顿、换气和信息释放。
7. **词语层**：最后才处理近距离重复、固定搭配和过密的高级词。

## 一、网文叙述口语化

### 目标

把正文写成“有人在给读者讲这件事”，而不是“把事件整理成报告”。对白当然要自然，旁白也要有口气。口语化重点不是增加网络梗，而是降低书面阻力，让用户用嘴读时不绕、不硬、不容易在句中迷路。

优先做四件事：

1. **常用词替代过度书面词**：把“进行观察”改为“看了看”，把“陷入沉思”改为“想了半天”，把“随后离开”改为“接着走了”。题材必要的时代词、专业词和风格词保留。
2. **抽象名词还原成动作**：把“产生恐惧”“表达不满”“作出决定”尽量落到“手抖了一下”“骂了两句”“他拍板了”。原文已经自然时不要硬改。
3. **给句子加自然的说话连接**：按语境使用“结果、这下、其实、反正、没想到、也就、还、才、倒是、哪知道”等，让上一拍和下一拍接得上。不要每句都加，也不要让叙述变成口头禅堆积。
4. **保留一点人的不完美**：允许补说、重复、停顿、半句、轻微绕远和不完全对称的句子。它们要帮助听者理解或体现态度，不能只是随机加废话。

### 口语化但不低幼

不要把所有词都换成俚语、热梗或网络缩写。古代、民俗、悬疑、年代和专业题材可以有自己的词，只需要把连接、解释和人物反应写得更像人在说。可以少量保留或故意加入不影响理解的口语省略、搭配松动、说半截和自我改口；不要为了“像人”主动制造错别字、错人名、错数字、错误知识和无法理解的病句。

### 允许的自然冗余

- 重要信息说完后，角色反应里再带到一次；
- 动作之间保留“想了想、停了一下、结果、这才”等小过渡；
- 先说错或先下判断，再用一句话自己补正；
- 关键落点前多绕半拍，或用一个短句停住；
- 同一意思用近似但不完全相同的说法重复一次，体现强调、迟疑或吐槽。

控制方法是“有功能的拖沓”：每一处冗余都应该让听者更容易跟上、让人物更像本人，或让情绪多停一拍。没有功能的套话、同义词连换和解释性复述仍然删。

### 口语化改写示例

| 书面/过度压缩 | 口语化听读写法 |
|---|---|
| 他对此事进行了判断，随后作出了离开的决定。 | 他看了看，转身就走。想了想，又回头补了一句：“算了。” |
| 由于伤势严重，他无法继续前进。 | 伤得太重了。他想往前走，腿没听他的。 |
| 她意识到自己可能陷入了危险之中。 | 她往后一看，心里咯噔一下。坏了，后面有人。 |
| 一切都在按照计划有条不紊地进行。 | 事情看着挺顺。至少现在还顺。 |
| 他表现出了难以掩饰的愤怒。 | 他没吭声，只把杯子往桌上一放。声音有点重。 |

右栏不要求原样套用。保留原文的剧情、视角和人物脾气，再按上下文决定需要多口语、多少停顿、多少重复。

## 二、结构与场景

### 系统、金手指和设定

- 面板、系统提示和规则说明可以保留，只在信息过密或打断场景时处理。
- 能让读者从角色选择和后果中理解的内容，不必重复解释。
- 金手指首用是否失败、是否有代价，取决于题材和本章目标，不是通用硬规则。
- 不为了“打散模板”强行加入配角、闲事或无意义物件；新增内容必须产生叙事作用。

### 开头和结尾

- 若开头连续交代时间、地点、天气却没有动作，可把一个具体物件或正在发生的选择提前。
- 若结尾在剧情已经落地后再总结道理，先尝试删掉总结，只保留动作、物件、未说出口的话或新的具体结果。
- 弱钩子不是固定格式；悬念、情绪落点和完整收束都可以成立。

## 三、段落与对白

### 段落调整

- 先看 `paragraphs` 的字数和句数，再看段内是否混合多个功能。
- 超过 60 字只代表需要检查，不代表必须拆；短段占比也不设通用目标。
- 一个段落若同时完成背景介绍、动作转折、人物解释和结论，可按功能拆开。
- 一句完整且有意拉长的叙述可以独占一段；对话是否独占一段按阅读清晰度处理。

### 叙述改对白

只有章节目标需要交互时才考虑这一步：

1. 景物描写：先让人物做一个会改变现场的动作，景物保留必要的一笔。
2. 心理说明：若另一角色确实能观察或追问，再把心理转成有立场的回答；否则保留内心叙述。
3. 事件推进：让争执、误解、拒绝或选择通过说话发生，而不是用对白复述已知信息。
4. 情绪高潮：对白之后接外部反应或实际后果，不自动追加情绪标签和总结。

`some` 只要求出现有作用的对白；`driving` 才检查连续叙述跨度，但低对白占比只是复核信号。不要每隔固定字数补一句，也不要为了提高比例制造问答。

## 四、句子与节奏

### 句长

- 使用句长分布的中位数、P10、P90和变异系数定位“过度整齐”的局部，而不是追求平均句长。
- 连续多句长度接近时，可以保留其中一条长句，把另一条改成动作、停顿或短回应；也可以整合重复信息。
- 句子很长不自动等于问题；它可能承载铺陈、观察或复杂行动。先确认可读性和语义层次。
- 朗读时长句要有可感的落点：先发生什么、人物怎么反应、结果落在哪里。一个句子装不下时，按动作或认知变化拆，不按固定字数硬切。
- 不要把所有句子改成“主语+动作+结果”的同一个骨架。口语有短句，也有逗号串起来的长句，还有说到一半的停顿。

### 标点与连接

- 逗号密度只作节奏线索，不通过堆逗号制造所谓人味。
- 破折号、感叹号、语气词可以符合题材；只在连续使用造成语气单一或影响理解时局部调整。
- 连接词按叙述者和角色声音选择，不建立“某词出现即替换”的禁表。

### 句首与重复

- `sentenceStartRepeatRatio` 高时，先找连续机械区；不要全章删除“他”“她”或角色名。
- 完全重复句、八字短语重复，先判断是否是口头禅、术语、咒语、回环或有意强调。
- 只改无意重复：换观察角度、改变动作顺序、删掉多余的一句，优先于同义词替换。

## 五、声音与具体性

- 用人物的目标、知识边界和当下代价拉开声线，不靠给每人分配固定口癖。
- 情绪可以通过动作、物件、节奏或选择体现，但直接写“他很紧张”并非自动错误；判断它是否比具体结果更弱。
- 具体细节要服务现场：一个被捏皱的票根比随机添加三个生活物件有效。
- 保留作者已有的方言、口头禅、句法和题材术语，除非它们真的造成误解或密集重复。
- 用户要求整体口语化时，降低叙述中的论文式、公告式和过度古雅表达；保留作者的态度、吐槽、冷感、夸张方式和人物差异。原文的“漂亮”不等于必须保留的复杂句法。

## 六、局部编辑契约

统计后优先用 `edit.lineEdits` 或 `edit.paragraphEdits`，不要无理由全量覆盖：

```json
{
  "path": "chapters/{id}",
  "expectedSourceHash": "text_stats 返回的 sourceHash",
  "lineEdits": [
    {
      "startLine": 12,
      "endLine": 13,
      "expectedText": "当前第十二行\n当前第十三行",
      "newText": "修改后的两行"
    }
  ]
}
```

`startLine` 从 1 开始；省略 `endLine` 表示单行替换。`expectedText` 必须与当前行内容一致，不包含行边界换行符；多个区间不能重叠。校验失败就重新读取和统计，不强行覆盖。

## 七、修改后复核

1. 对修改后正文再次调用 `text_stats`，检查目标指标是否改善且没有引入新的集中重复。
2. 调用 `text_compare({ before, after, terms })`，检查数字、百分比、保护词和对白数量变化。
3. `protected-number-removed` 或 `protected-term-removed` 出现时先停下确认事实；对白减少是人工复核提示，不代表必错。
4. 把修改片段从头到尾读一遍，确认叙述和对白都能顺着说，常用词够多，换气点自然，没有连续高级词、绕口套句或需要回读的指代。
5. 确认自然冗余、补说和轻微不工整是有功能的；同时确认没有新增错别字、事实错误、专名错误或严重歧义。
6. 确认语义自然、角色仍像原作者，且没有为了指标产生新腔调。
7. 只报告实际改动和仍需作者确认的地方。

## 最小改动纪律

- 说不出具体叙事收益的改动不做。
- 不把普通词语、长段、少对白、破折号或零感叹号自动判为问题；也不把自然重复、补说、半句和轻微拖沓自动判为问题。
- 不用同义词替换伪装成深度改写，也不复制整段原文做“降 AI”。
