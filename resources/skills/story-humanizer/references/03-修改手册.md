# 03 修改手册

> 只修已定位的问题。保留作者的视角、口头习惯和题材词汇，优先做能说明收益的局部替换，不在统计阶段起草整章新稿。

## 修改前

1. 保存正文原文和 `text_stats.sourceHash`。
2. 从诊断报告中挑选最多一到三个最高收益的局部问题。
3. 把时间、数字、人物、地点、专名、关键物件和对白意图列为保护项，传给 `text_compare`。
4. 读目标行和前后文，确认修改不会跨越视角、时间线或场景边界。

## 修改顺序

1. **保真层**：纠正或恢复事实、视角、因果和专名。
2. **场景层**：删掉重复解释，让行动、关系或认知真正发生变化。
3. **段落层**：只拆信息混杂的大段，或合并机械碎段。
4. **句子层**：处理重复句式、空泛总结和不自然连接。
5. **节奏层**：让长短变化服务于紧张、停顿和信息释放。
6. **词语层**：最后才处理近距离重复和固定搭配。

## 一、结构与场景

### 系统、金手指和设定

- 面板、系统提示和规则说明可以保留，只在信息过密或打断场景时处理。
- 能让读者从角色选择和后果中理解的内容，不必重复解释。
- 金手指首用是否失败、是否有代价，取决于题材和本章目标，不是通用硬规则。
- 不为了“打散模板”强行加入配角、闲事或无意义物件；新增内容必须产生叙事作用。

### 开头和结尾

- 若开头连续交代时间、地点、天气却没有动作，可把一个具体物件或正在发生的选择提前。
- 若结尾在剧情已经落地后再总结道理，先尝试删掉总结，只保留动作、物件、未说出口的话或新的具体结果。
- 弱钩子不是固定格式；悬念、情绪落点和完整收束都可以成立。

## 二、段落与对白

### 段落调整

- 先看 `paragraphs` 的字数和句数，再看段内是否混合多个功能。
- 超过 60 字只代表需要检查，不代表必须拆；短段占比也不设通用目标。
- 一个段落若同时完成背景介绍、动作转折、人物解释和结论，可按功能拆开。
- 一句完整且有意拉长的叙述可以独占一段；对话是否独占一段按阅读清晰度处理。

### 叙述改对白

只有章节目标需要交互时才考虑这一步：

1. 景物描写：先让人物做一个会改变现场的动作，景物保留必要的一笔。
2. 心理说明：若另一角色确实能观察或追问，再把心理转成有立场的回答；否则保留内心叙述。
3. 事件推进：让争执、误解、拒绝或选择通过说话发生，而不是用对白复述已知信息。
4. 情绪高潮：对白之后接外部反应或实际后果，不自动追加情绪标签和总结。

`some` 只要求出现有作用的对白；`driving` 才检查连续叙述跨度，但低对白占比只是复核信号。不要每隔固定字数补一句，也不要为了提高比例制造问答。

## 三、句子与节奏

### 句长

- 使用句长分布的中位数、P10、P90和变异系数定位“过度整齐”的局部，而不是追求平均句长。
- 连续多句长度接近时，可以保留其中一条长句，把另一条改成动作、停顿或短回应；也可以整合重复信息。
- 句子很长不自动等于问题；它可能承载铺陈、观察或复杂行动。先确认可读性和语义层次。

### 标点与连接

- 逗号密度只作节奏线索，不通过堆逗号制造所谓人味。
- 破折号、感叹号、语气词可以符合题材；只在连续使用造成语气单一或影响理解时局部调整。
- 连接词按叙述者和角色声音选择，不建立“某词出现即替换”的禁表。

### 句首与重复

- `sentenceStartRepeatRatio` 高时，先找连续机械区；不要全章删除“他”“她”或角色名。
- 完全重复句、八字短语重复，先判断是否是口头禅、术语、咒语、回环或有意强调。
- 只改无意重复：换观察角度、改变动作顺序、删掉多余的一句，优先于同义词替换。

## 四、声音与具体性

- 用人物的目标、知识边界和当下代价拉开声线，不靠给每人分配固定口癖。
- 情绪可以通过动作、物件、节奏或选择体现，但直接写“他很紧张”并非自动错误；判断它是否比具体结果更弱。
- 具体细节要服务现场：一个被捏皱的票根比随机添加三个生活物件有效。
- 保留作者已有的方言、口头禅、句法和题材术语，除非它们真的造成误解或密集重复。

## 五、局部编辑契约

统计后优先用 `edit.lineEdits` 或 `edit.paragraphEdits`，不要无理由全量覆盖：

```json
{
  "path": "chapters/{id}",
  "expectedSourceHash": "text_stats 返回的 sourceHash",
  "lineEdits": [
    {
      "startLine": 12,
      "endLine": 13,
      "expectedText": "当前第十二行\n当前第十三行",
      "newText": "修改后的两行"
    }
  ]
}
```

`startLine` 从 1 开始；省略 `endLine` 表示单行替换。`expectedText` 必须与当前行内容一致，不包含行边界换行符；多个区间不能重叠。校验失败就重新读取和统计，不强行覆盖。

## 六、修改后复核

1. 对修改后正文再次调用 `text_stats`，检查目标指标是否改善且没有引入新的集中重复。
2. 调用 `text_compare({ before, after, terms })`，检查数字、百分比、保护词和对白数量变化。
3. `protected-number-removed` 或 `protected-term-removed` 出现时先停下确认事实；对白减少是人工复核提示，不代表必错。
4. 朗读修改片段，确认语义自然、角色仍像原作者，且没有为了指标产生新腔调。
5. 只报告实际改动和仍需作者确认的地方。

## 最小改动纪律

- 说不出具体叙事收益的改动不做。
- 不把普通词语、长段、少对白、破折号或零感叹号自动判为问题。
- 不用同义词替换伪装成深度改写，也不复制整段原文做“降 AI”。
