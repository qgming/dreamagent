# 02 问题诊断与定位

> 这一步回答“哪里值得改、为什么改、改到什么范围”，尤其要找出网络小说里的书面腔和听读卡顿。不把统计异常直接等同于 AI，也不把一个格式偏好升级成通用规则。

## 使用顺序

1. 先确认章节目标、视角、题材惯例、用户明确要保留的声音，以及是否启用整体口语化听读目标。
2. 阅读 `text_stats` 的 `summary`、`paragraphs`、`profile.segments`、`profile.findings` 和 `baseline`。
3. 回读命中行上下文，判断它是局部问题、题材选择，还是作者有意形成的节奏。
4. 只选择最小的修改层级；没有明确收益的地方保留原文。
5. 修改后重新统计，并用 `text_compare` 做事实与结构保真复核。

## 诊断分层

| 层级 | 要回答的问题 | 常见信号 | 修改方向 |
|---|---|---|---|
| 1 保真 | 时间、数字、专名、视角和因果是否稳定 | `text_compare` 有减少项 | 先恢复事实，再谈文风 |
| 2 口语与听读 | 叙述是否像在给人讲事，能否顺着读出来 | 公文连接、复杂套句、四字格堆叠、长句无落点 | 换常用词和动词，拆开嵌套，补自然连接；不把全文切成短句 |
| 3 场景功能 | 这一段是否推动事件、关系或认知变化 | 解释很多但目标没有变化 | 删除重复解释或补具体结果 |
| 4 声音 | 角色和叙述者是否有可辨认的立场 | 每个人都用同一腔调，或叙述像说明书 | 保留态度和题材词，降低统一的书面腔 |
| 5 节奏 | 长短变化是否服务于场景 | 句长/段长局部过度整齐，或短句切得像提纲 | 合并或拆分具体机械区域，给朗读留落点 |
| 6 重复 | 是否有无意的整句、句首或固定搭配复用 | `repeated-sentences`、`repeated-phrases` | 保留有意回环和自然冗余，局部换观察角度 |
| 7 格式 | 标点和段落是否影响阅读 | 对话边界、空行、面板拥挤 | 修可读性，不追求统一模板 |

## 症状到检查动作

| 症状 | 先查什么 | 不要直接做什么 |
|---|---|---|
| 句末密度偏高/偏低 | 是否连续出现“一句一段”或过度合并 | 不为了数字机械拆句、并句 |
| 段落偏长 | 是否把动作、背景、解释和结论塞在一起 | 不因超过 60 字就全部拆开 |
| 短段偏少 | 短段是否能形成有效停顿 | 不为凑占比切碎完整叙述 |
| 句首重复 | 重复是否集中在同一场景，是否是角色口头禅 | 不强行替换所有“他/她/名字” |
| 完全重复句或八字短语多 | 是否是有意回环、术语、咒语或重复强调 | 不只换同义词掩盖问题 |
| 对话少 | 本章是否由交互推动 | 不为提高百分比插入无功能对白 |
| 叙述太书面 | 句子像报告、摘要或论文，人物动作被抽象名词盖住 | 不要把每个词都换成俚语，也不要只改对白 |
| 叙述太干 | 信息都对，但像剧情梗概，动作之间没有过渡和反应 | 不要凭空塞满环境细节；补一两处自然的停顿、补说或结果 |
| 读起来卡 | 一句塞太多层关系，或连续四字格、冷僻词、无落点长句 | 不按固定字数切句；先找真正的换气点和动作落点 |
| 句子过分整齐 | 每句都完整、对称、结论明确，像机器逐项播报 | 不故意制造错别字；允许少量半句、重复和松动连接 |
| `dialogueExpectation=some` 无对白 | 是否确实需要至少一个交互节点 | 只补能改变信息或关系的对白 |
| `dialogueExpectation=driving` 占比低 | 对话驱动章节是否有连续叙述跨度 | 不把 25%-40% 当所有章节目标 |
| 基线距离高 | 参考样本是否同作者、同题材、同阶段 | 不把距离当质量分或作者认证 |
| 第三方 AIGC 结果波动 | 检测器、版本、文本长度和分段是否一致 | 不把一次检测值当优化目标 |

## 重点复核区

### 系统面板与设定信息

`【】` 面板不是自动错误。先看信息是否重复、是否阻断场景，以及读者是否需要此刻看到完整字段。只有信息堆叠影响阅读时，才考虑拆成行动结果、角色反应、信物或简短转述。

### 对话策略

- `none`：允许整章没有对白，重点看场景功能和叙述节奏。
- `some`：只检查是否出现有作用的有效对白，不检查固定占比和均匀分布。
- `driving`：对白是主要推进手段时，低于 10% 只作软提示，再回读连续无对白的段落。

对白必须有理由：改变信息、目标、关系、权力、选择或现场反应中的至少一项。补对白之前，先确认旁白本身不是更自然的表达。

### 叙述口气与听书

网络小说的“口语化”首先作用于叙述。叙述者可以有一点聊天式的推进：先说一件事，再顺手补一句；先下判断，再被现场打脸；同一个重点在动作和反应里回响一次。这样做是为了让听者在没有画面和排版辅助时跟得住，不是为了把文字写成聊天记录。

优先处理这些位置：

- 书面连接词把动作切成一节一节的说明，如“随后、与此同时、由此、综上”；
- 抽象名词替代了本来可以直接说的动作，如“进行了观察”“产生了恐惧”“处于等待状态”；
- 句子结构太完整，人物没有反应，段落像剧情摘要；
- 连续多个高级词、四字格或多层定语，朗读时没有自然停顿。

可以保留这些东西：角色和叙述者的口头禅、自然重复、补说、停半句、轻微拖沓，以及题材必须的古风、年代感或专业词。所谓“故意犯错”主要是口语里的不完整和不工整，不是错别字、事实错漏或让人听不懂的病句。

### 词语和模板

单个“仿佛”“突然”“微微”等普通词不能证明文本有问题。只有当同一词语在近距离反复、与固定搭配绑定、只宣布情绪而没有结果，或与上下文不匹配时，才定位到具体句子复核。用户要求口语化时，优先降低密集的书面连接和抽象表达，但不要维护“见到某词就替换”的一级禁词表。

### 作者基线

优先使用用户认可的同作者章节。查看 `baseline.labels` 确认样本来源，再看各指标的中位数、范围和偏离量。不同视角、高潮/过渡章节、对话/独白章节出现差异很正常，距离高只触发解释，不触发自动改写。

## 局部定位报告

每个候选问题至少记录：行号或段号、统计信号、上下文证据、叙事影响、拟采用的最小动作。没有上下文证据的“像 AI”判断不进入修改清单。

推荐格式：

```text
位置：第 12-14 行 / 第 4 段
信号：句首重复率偏高，且三句连续以同一主语开头
判断：本处连续动作既有句首重复，也有说明书式连接；需要改口气，但不是全章规则
动作：保留关键动作，将一处书面连接换成自然补说，另一处接场景结果
复核：重新 text_stats，朗读修改片段，并检查 text_compare 的数字、专名和对白提示
```

## 诊断结论

最终只输出三类结论：需要修改、可以保留、需要作者确认。把“可测结构信号”“人工质量判断”“外部检测反馈”分开记录，避免用一个总分掩盖实际取舍。
