# 01 自动检查与定位

> 先过 check_prose，再人工朗读定位。工具只覆盖硬禁令与模型化形状，不能判断文章有没有人。

## 自动检查

对项目中的文章调用：

```text
check_prose({ path: "chapters/{id}" })
```

临时正文传 `content`。返回汉字数、硬性违规（failures）与需人工判断项（warnings），每项带行号与原文摘录；`counts` 汇总翻案句、黑话、路标、抒情词、名词化、连词密度、句长变异等计数。不要手工数句号、字数、段落或禁词。

`failures` 是硬性违规（必须改），`warnings` 是需人工判断项（结合语境决定）。列表不是第三方 AIGC 检测值，不预测作者身份。

## 全文指标

以正文（不含标题）为样本。check_prose 已覆盖的指标直接以工具结果为准，其余按人工朗读与上下文判断：

| 指标 | 复核方式 | 说明 |
|---|---|---|
| 句末密度 | 人工朗读 | 承接 check_prose 的句长变异提示，不机械拆句并句 |
| 段落密度/短段/长段 | 人工朗读 | 只定位信息堆叠的大段，不用绝对段数判定 |
| 听读卡顿 | 默读/朗读 | 多层定语、嵌套从句、连续四字格、拗口词组 |
| 对话占比/轮次 | 按章节功能判断 | 本章不需要对话则不检查；对话驱动章节明显偏低时复核 |
| 破折号/感叹号/语气词 | 按题材判断 | 可选风格项，不自动扣分 |

## 切段定位局部异常

按 check_prose 命中的行号与摘录，把问题定位到具体句段。逐段看：

- check_prose 提示句长变异系数过低 → 句子长度过于均匀，节奏高危
- check_prose 提示连续短促单句段 → 检查是否在排队喊结论
- 连续出现“因此/随后/与此同时/此刻/不禁/由此”等书面连接，或一段里抽象名词多于具体动作 → 书面腔候选
- 连续多句像说明书一样完整、工整、没有弱连接和补说 → 口语节奏候选
- 读出时需要在一个句子中间反复找落点，或连续多个四字格互相挤在一起 → 听读候选

标记每段：位置、症状类型（叙述性/独白性/景物性/节奏性）、疑似原因。这是下一步修改的靶子。

## 口语化听读复核

用户要的是“像人讲故事”，不是“像聊天记录”。逐段检查：

- 叙述者是否会自然地用“结果、这下、其实、反正、没想到、也就、还、才”等弱连接，而不是每句都像报告结论。
- 是否有适量的补说、重复、停顿和半句落点，让听者有时间跟上人物的动作和情绪。
- 常用词是否够多；“展开、进行、予以、处于、由此、随即、顷刻”等书面词是否在用户目标下显得过密。
- 句子是否能顺着读出来。长句可以保留，但要有自然落点，不能连续堆三层以上修饰、多个抽象判断或一串四字格。
- 口语毛边是否是有意且可理解的：允许松一点、绕一点、重复一点，不允许错别字、人名数字错误、事实错误或造成歧义。

这一组检查不直接换算成分数。它要落到具体句段和修改收益上，避免为了“口语”把所有句子砍成电报体。

## 作者基线

有用户认可的同作者章节时，手动对比其句长、段落、连词与重复习惯：把当前稿与参考章节分别过一遍 check_prose，比较 counts 与命中项。差异只表示当前文本可能属于不同题材、场景或阶段；参考样本是否可比需先确认。

## 输出检测报告

```
===== 文本质量复核报告 =====
文件：{文件名}
总字数：{check_prose.hanCount}
硬性违规：{failures 数量与行号}
需人工判断：{warnings 数量与行号}

【高危片段】（按危害排序）
1. 第12-18段：句首重复或句长分布异常，先检查是否是同一场景的有意节奏
2. 第30-35段：连续叙述跨度较长，回读对白功能

【修改意见】（按优先级）
1. 最高：xxxx → 改成 yyyy
2. 次高：xxxx → 改成 yyyy

【口语化与听读】
- 叙述口气：达标 / 部分达标 / 需处理
- 朗读卡顿：位置与原因
- 自然冗余/补说：保留项与需要收紧的项

【达标项】
- 已达标：句末密度、段落数……
==========================
```

修改意见排序：先修复事实/语义漂移，再处理完全重复和明显模板，最后才调整节奏与词语。内置 5 篇样文用于回归测试，不作为所有作者的硬标准。

## 校准

如果用户提供第三方检测结果，记录检测器名称、版本、日期、文本长度和分段结果。不同检测器之间不要混合成一个“真实 AI 率”，只用于观察反馈。
