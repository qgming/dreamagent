# 01 统计与复核

> 流程入口。先量化全文，再定位书面腔、听读卡顿、重复、节奏和对话风险，最后输出可解释的复核报告。不预测作者身份或第三方 AIGC 分数。

如果处理对象是网络小说，默认按“口语化听读模式”复核。这个模式检查的是叙述和对白整体是否像人在讲故事，不能只看引号里的对白。口语化程度主要靠上下文和朗读判断，统计数字只能提供线索。

## 工具优先

对项目中的文章，先调用：

```text
text_stats({
  path: "chapters/{id}",
  profile: "story-humanizer",
  dialogueExpectation: "none",
  referencePaths: ["chapters/{同作者认可样本}"],
  terms: ["需要额外检查的词"]
})
```

临时正文可传 `content`，不需要先写入文章。优先使用工具返回的 `summary`、`paragraphs`、`terms`、`profile.segments` 和 `profile.findings`，不要让模型手工数句号、字数、段落或禁词。

工具中的行号是正文真实换行行号，段号按空行分隔。命中位置包含行号、段号和列号；高频词会按行聚合，位置样本可能受 `maxMatches` 限制。

## 第一步：统计全文指标

以正文（不含标题）为样本统计。能由 `text_stats` 返回的指标均以工具结果为准：

| 指标 | 统计方法 | 样文参考 | 复核条件 |
|---|---|---|---|
| 句末密度 | （。！？）÷ 总字数 × 1000 | 23-50/千字 | <20 或 >55 软提示；<15 或 >65 才算极端 |
| "的"密度 | "的" ÷ 总字数 × 1000 | 仅作描述 | 低时检查修饰是否过少，不为凑数添加形容词 |
| 段落密度 | 段落数 ÷ 总字数 × 1000 | 参考作者样本 | 只定位信息堆叠的大段，不用绝对段数判定 |
| 短段占比 | ≤20 字段 ÷ 总段数 | 19-54% | <15% 才提示 |
| 超长段 | >60 字段数 | 0-16 段 | ≥17 且占比≥17% 才提示；≥25 且占比≥25% 才算极端 |
| 句长分布 | p10 / 中位数 / p90 / 标准差 / 变异系数 | 与作者样本比较 | 关注是否过度均匀，不追求固定平均句长 |
| 听读卡顿 | 多层定语、嵌套从句、连续四字格、拗口词组 | 人工朗读或默读复核 | 找到一口气读不完、需要回读或不易断气的位置 |
| 书面腔 | 公文式连接、抽象名词串、名词化动作、过度古雅表达 | 与用户目标和题材比较 | 用户要口语化时优先处理；不把题材术语一律现代化 |
| 逗号密度 | 逗号数 ÷ 可见字数 × 100 | 与作者样本比较 | 只作节奏线索，不鼓励堆逗号 |
| 句首重复率 | 重复句首数 ÷ 句子数 | 越低越自然，但题材可例外 | ≥25% 仅提示局部复核 |
| 完全重复句 | 规范化后完全相同的句子数 | 0 为佳 | 只定位重复句，不自动改写 |
| 对话占比 | 引号内字符 ÷ 总字数 | 按 `dialogueExpectation` | `none` 不检查；`some` 只检查是否出现；`driving` <10% 软提示 |
| 对话轮次 | 引号片段数、平均对白长度 | 与场景目的比较 | 不用轮次替代对白质量判断 |
| 破折号 | —— 或 单 — 计数 | 样文可出现 | 仅作可选风格复核，不自动扣分 |
| 情感标点 | 感叹号数 | ≥3（可选） | =0 不扣分 |

## 第二步：自动结构分与人工复核分开

| # | 检查项 | 触发 | 扣分 | 修复指引 |
|---|---|---|---|---|
| 1 | 句末密度 | 超出软范围；达到极端范围 | 5；15 | 先看局部节奏，不机械合并或拆句 |
| 2 | 段落密度 | 低于作者样本且出现信息堆叠 | 仅提示 | 只拆混合了多个功能的段落 |
| 3 | 句长分布 | 句子过度同长或局部碎片化 | 仅提示 | 见 03·节奏 |
| 4 | 重复句式 | 完全重复句、句首或八字短语异常集中 | 仅定位 | 先判断是否是角色口头禅、回环或有意复现 |
| 5 | 对话策略 | `some` 无对白；`driving` 对话占比低于 10% | 5；0（软提示） | 不以对白百分比替代场景功能 |
| 6 | 破折号/语气词 | 出现或缺少 | 0 | 只按题材和语气决定是否改 |
| 7 | 结构模板 | 五段式、说明书、开头三连 | 仅人工判断 | 不因命中一个结构词就改骨架 |
| 8 | 叙事单调 | 角色目标、冲突、细节长期不变化 | 仅人工判断 | 加具体行为或关系变化，不强塞配角 |

### 特殊规则
- 【】系统面板**不因格式扣分**（系统文合法）；只有信息堆叠或打断场景时才考虑转述成对话、行动结果或信物。
- 感叹号 =0 不扣分（冷叙述合法），情绪点可加"！/啊/吧"。
- 不设置一级禁词。普通词语的单次出现不扣分，只有重复、固定搭配密集或语义空泛时才进入人工复核。
- 工具的 `profile.structureScore` 是自动结构分：100 起算，error 扣 15，warning 扣 5，info 不扣分；旧字段 `score` 仅为兼容保留。它不是第三方 AIGC 检测值。

自动分只覆盖工具能稳定测量的结构指标。口语化、听读流畅、角色声线、开头切入、五段式、结尾弱钩子等语义项仍需人工判断，不能伪装成精确数字。

## 第三步：切段定位局部异常

工具的 `profile.segments` 只是按字数近似切出的诊断片段，不是第三方检测器的模拟，也不代表某一段的“AI 概率”。只有在章节确实需要对话时，才把对话跨度作为局部线索。逐段看：

- `driving` 且引号内字符占比 <10% → 需要复核的片段（纯叙述/独白/景物）
- 平均句长几乎一致 → 节奏高危
- `driving` 且连续 3 句以上无对话 → 叙述跨度提示；`some` 不做跨度和占比扣分
- 用户要求口语化时，连续出现“因此/随后/与此同时/此刻/不禁/由此”等书面连接，或一段里抽象名词多于具体动作 → 书面腔候选片段
- 连续多句像说明书一样完整、工整、没有弱连接和补说 → 口语节奏候选片段
- 读出时需要在一个句子中间反复找落点，或连续多个四字格互相挤在一起 → 听读候选片段

标记出每段：位置（第几段~第几段）、症状类型（叙述性/独白性/景物性/节奏性）、疑似原因。这是下一步修改的靶子。

## 口语化听读复核

用户要的是“像人讲故事”，不是“像聊天记录”。逐段检查：

- 叙述者是否会自然地用“结果、这下、其实、反正、没想到、也就、还、才”等弱连接，而不是每句都像报告结论。
- 是否有适量的补说、重复、停顿和半句落点，让听者有时间跟上人物的动作和情绪。
- 常用词是否够多；“展开、进行、予以、处于、由此、随即、顷刻”等书面词是否在用户目标下显得过密。
- 句子是否能顺着读出来。长句可以保留，但要有自然落点，不能连续堆三层以上修饰、多个抽象判断或一串四字格。
- 口语毛边是否是有意且可理解的：允许松一点、绕一点、重复一点，不允许错别字、人名数字错误、事实错误或造成歧义。

这一组检查不直接换算成分数。它要落到具体句段和修改收益上，避免为了“口语”把所有句子砍成电报体。

## 第四步：人工质量检查（不伪装成自动分）

- 场景是否有明确目的，段落是否推动事件、关系或认知变化。
- 角色是否有可辨认的语言习惯、立场和代价，而不是每人同一种腔调。
- 细节是否具体有效，是否存在不必要的解释和总结。
- 对话是否改变信息、目标或权力关系，而不是为了提高比例插入对白。
- 修改后是否保留时间线、数字、专名、视角和对白意图。

## 第五步：作者基线比较

传入 `referencePaths` 或 `referenceContents` 后，工具会返回参考来源标签、样本数、每项当前值、参考中位数、范围、偏离量和总体 `distance`。参考样本最多 20 篇、合计 500000 字符；距离高只表示当前文本可能属于不同题材、场景或阶段，必须先确认参考样本是否可比。

## 第六步：输出检测报告

```
===== 文本质量复核报告 =====
文件：{文件名}
总字数：{字数} | 段数：{段数}
结构分：{structureScore}/100
作者基线：{distance 或 未提供}

【高危片段】（按危害排序）
1. 第12-18段：句首重复或句长分布异常，先检查是否是同一场景的有意节奏
2. 第30-35段：连续叙述跨度较长，仅在 `driving` 章节复核对白功能

【修改意见】（按优先级）
1. 最高：xxxx → 改成 yyyy
2. 次高：xxxx → 改成 yyyy

【口语化与听读】
- 叙述口气：达标 / 部分达标 / 需处理
- 朗读卡顿：位置与原因
- 自然冗余/补说：保留项与需要收紧的项

【达标项】
- 已达标：句末密度、段落数……
==========================
```

修改时优先使用工具返回的定位：先 `read` 高风险行附近的上下文，再用 `edit` 的 `lineEdits` 或 `paragraphEdits` 做局部替换。`lineEdits` 支持 `startLine`、可选 `endLine`、`expectedText` 和 `newText`，因此可以逐行或连续多行替换；每个替换提供 `expectedText`，并避免编辑区间重叠。若统计结果带有 `sourceHash`，同时传入 `expectedSourceHash`。正文发生变化时停止并重新统计，不要强行覆盖。

修改意见排序：先修复事实/语义漂移，再处理完全重复和明显模板，最后才调整节奏与词语。内置 5 篇样文用于回归测试，不作为所有作者的硬标准。

## 校准

如果用户提供第三方检测结果，记录检测器名称、版本、日期、文本长度和分段结果。不同检测器之间不要混合成一个“真实 AI 率”，只用于观察反馈。
